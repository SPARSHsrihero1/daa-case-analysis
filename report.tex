%======================== ABSTRACT ========================
\begin{abstract}
The efficiency of an algorithm is rarely determined by its size alone; the
structure of the input plays an equally critical role. This report presents a
rigorous study of \emph{best, worst, and average case analysis}---the three
fundamental paradigms used in Design and Analysis of Algorithms to characterise
algorithmic performance across all possible inputs. Using three canonical
algorithms---Linear Search, Insertion Sort, and Quick Sort---we derive closed-form
complexity bounds for each case through summation techniques, inversion counting,
and the Master Theorem. We further clarify the common misconception that equates
asymptotic notation ($O$, $\Omega$, $\Theta$) with the three input cases.
An interactive animation, built in Python using \texttt{matplotlib}, demonstrates
both Linear Search and Insertion Sort step by step under all three cases, with
live operation counters and user-controlled navigation. The central takeaway is
that worst-case analysis provides the only \emph{unconditional} performance
guarantee, making it indispensable for safety-critical systems.
\end{abstract}

%======================== 1 INTRODUCTION ========================
\section{Introduction}

An \textbf{algorithm} is a finite, deterministic procedure that transforms an
input into a desired output. In practice, two questions arise immediately after
establishing correctness: \emph{how fast does it run?} and \emph{how much memory
does it need?} These are captured respectively by time complexity and space
complexity---both expressed as functions of the input size~$n$.

A critical subtlety, however, is that the running time of most non-trivial
algorithms is not determined by $n$ alone. It depends equally on the
\emph{arrangement and distribution} of the input elements. Consider a library
with $n$ books on an unsorted shelf. If the book you want happens to be the
first one you pick up, you finish in one step; if it is the last, you need $n$
steps. Searching that library is the same problem at the same scale, yet the
effort differs by a factor of $n$.

This input-dependence motivates three complementary analytical lenses~\cite{cormen2022}:
\begin{itemize}
  \item \textbf{Best-case analysis} --- performance on the most favourable input.
  \item \textbf{Worst-case analysis} --- performance on the most adversarial input.
  \item \textbf{Average-case analysis} --- expected performance under a probability
        distribution over all inputs.
\end{itemize}

This report analyses all three cases for Linear Search, Insertion Sort, and Quick
Sort, which together cover the three main algorithmic strategies (scan,
incremental construction, and divide-and-conquer) taught in CSEG3053.

%======================== 2 INTUITION ========================
\section{Intuition and Core Idea}

\begin{keyidea}
For a fixed input size~$n$, the number of operations an algorithm performs can
vary dramatically depending on how the data is arranged. Case analysis captures
this variation by identifying the \emph{minimum} (best), \emph{maximum} (worst),
and \emph{expected} (average) operation counts over all possible arrangements.
\end{keyidea}

Think of a security checkpoint at an airport. In the best case, your bag is clean
and the scanner clears you instantly. In the worst case, every item needs manual
inspection---maximum delay. On an average day, the queue moves at a predictable
rate determined by the typical mix of passengers. Algorithm case analysis applies
exactly this reasoning to computational problems.

Figure~\ref{fig:intuition} illustrates how the same input size~$n$ fans out into
three performance trajectories depending on the structural configuration of the data.

%======================== 3 MATHEMATICS ========================
\section{Mathematical Formulation}

Let $\mathcal{I}_n$ be the set of all valid inputs of size~$n$, and let $T(I)$
denote the number of primitive operations (comparisons, assignments, arithmetic
steps) executed by algorithm $\mathcal{A}$ on input $I\in\mathcal{I}_n$.

\subsection{Best-Case Complexity}
\begin{equation}
  T_{\text{best}}(n) = \min_{I\,\in\,\mathcal{I}_n} T(I)
  \label{eq:best}
\end{equation}
Equation~\eqref{eq:best} represents the minimum computational work over all
inputs of size~$n$. It identifies short-circuit conditions but provides no
general guarantee.

\subsection{Worst-Case Complexity}
\begin{equation}
  T_{\text{worst}}(n) = \max_{I\,\in\,\mathcal{I}_n} T(I)
  \label{eq:worst}
\end{equation}
Equation~\eqref{eq:worst} gives an \emph{absolute upper bound}: the algorithm
cannot exceed $T_{\text{worst}}(n)$ operations for any input of size~$n$. This
makes it the standard measure for reliability guarantees~\cite{cormen2022}.

\subsection{Average-Case Complexity}
Let $P(I)$ be the probability of encountering input $I$, with
$\sum_{I\in\mathcal{I}_n}P(I)=1$. The expected running time is:
\begin{equation}
  T_{\text{avg}}(n)
    = \mathbb{E}[T]
    = \sum_{I\,\in\,\mathcal{I}_n} P(I)\cdot T(I)
  \label{eq:avg}
\end{equation}
Under the \textbf{uniform distribution assumption} ($P(I)=1/|\mathcal{I}_n|$
for all $I$):
\begin{equation}
  T_{\text{avg}}(n) = \frac{1}{n!}\sum_{I\,\in\,\mathcal{I}_n} T(I)
  \label{eq:avguniform}
\end{equation}

\subsection{Notation vs.\ Case: A Critical Distinction}
A widespread misconception conflates asymptotic notation with input cases.
Table~\ref{tab:notation} clarifies the orthogonality of these two concepts.

%======================== 4 ALGORITHM ========================
\section{Algorithm / Procedure}

\subsection{Linear Search}
\begin{algorithm}[H]
\caption{LinearSearch($A$, $n$, $k$)}
\KwIn{Array $A[0\ldots n{-}1]$, integer $n$, target key $k$}
\KwOut{Index $i$ with $A[i]=k$, or $-1$ if absent}
\For{$i \leftarrow 0$ \KwTo $n-1$}{
  \If{$A[i] = k$}{\Return $i$\;}
}
\Return $-1$\;
\end{algorithm}

\subsection{Insertion Sort}
\begin{algorithm}[H]
\caption{InsertionSort($A$, $n$)}
\KwIn{Array $A[0\ldots n{-}1]$}
\KwOut{$A$ sorted in non-decreasing order (in place)}
\For{$j \leftarrow 1$ \KwTo $n-1$}{
  $\mathit{key} \leftarrow A[j]$\;
  $i \leftarrow j-1$\;
  \While{$i \geq 0$ \textbf{and} $A[i] > \mathit{key}$}{
    $A[i+1] \leftarrow A[i]$\;
    $i \leftarrow i-1$\;
  }
  $A[i+1] \leftarrow \mathit{key}$\;
}
\end{algorithm}

\subsection{Quick Sort (overview)}
\begin{algorithm}[H]
\caption{QuickSort($A$, \textit{lo}, \textit{hi})}
\KwIn{Array $A$, indices \textit{lo}, \textit{hi}}
\If{\textit{lo} $<$ \textit{hi}}{
  $\pi \leftarrow \text{Partition}(A,\textit{lo},\textit{hi})$
  \tcp*{$\Theta(n)$ work at each level}
  \text{QuickSort}$(A,\textit{lo},\pi-1)$\;
  \text{QuickSort}$(A,\pi+1,\textit{hi})$\;
}
\end{algorithm}

Core Python excerpt (full source in the repository):
\begin{lstlisting}[language=Python]
def insertion_sort(A):
    for j in range(1, len(A)):
        key = A[j]
        i = j - 1
        while i >= 0 and A[i] > key:   # inner loop: shift right
            A[i + 1] = A[i]
            i -= 1
        A[i + 1] = key                  # insert key at correct position
    return A
\end{lstlisting}

%======================== 7 ANALYSIS ========================
\section{Analysis}

\subsection{Per-Algorithm Case Derivations}

\subsubsection*{Linear Search}
\textbf{Best case.} Key at index 0: one comparison.
$T_{\text{best}}(n)=1=\Theta(1)$.

\textbf{Worst case.} Key absent or at index $n-1$: $n$ comparisons.
$T_{\text{worst}}(n)=n=\Theta(n)$.

\textbf{Average case.} Let $p$ be the probability the key is present.
If present, it is equally likely at any of the $n$ positions:
\begin{equation}
\mathbb{E}[T(n)]
  = \frac{p}{n}\sum_{i=1}^{n}i + n(1-p)
  = \frac{p(n+1)}{2}+n(1-p).
\end{equation}
For $p=1$: $\mathbb{E}[T(n)]=\tfrac{n+1}{2}=\Theta(n)$.

\subsubsection*{Insertion Sort}
\textbf{Best case.} Already sorted; the \texttt{while} condition fails
immediately each pass:
$T_{\text{best}}(n)=\sum_{j=1}^{n-1}1=n-1=\Theta(n)$.

\textbf{Worst case.} Reverse sorted; pass $j$ executes $j$ shifts:
\begin{equation}
T_{\text{worst}}(n)=\sum_{j=1}^{n-1}j=\frac{n(n-1)}{2}=\Theta(n^2).
\end{equation}

\textbf{Average case} (inversion analysis~\cite{knuth1998}). Each shift removes
one inversion. A random permutation has expected inversions
\begin{equation}
\mathbb{E}[\text{inv}]
  = \binom{n}{2}\cdot\frac{1}{2} = \frac{n(n-1)}{4},
\end{equation}
giving $T_{\text{avg}}(n)=\Theta(n^2)$.

\subsubsection*{Quick Sort}
\textbf{Best case.} Balanced pivot; recurrence
$T(n)=2T(n/2)+\Theta(n)$.
By Master Theorem Case~2 ($f(n)=\Theta(n^{\log_2 2})$):
$T_{\text{best}}(n)=\Theta(n\log n)$.

\textbf{Worst case.} Degenerate pivot (e.g.\ sorted array, last-element pivot):
$T(n)=T(n-1)+\Theta(n)$.
Unrolling: $T(n)=c\sum_{i=1}^{n}i=\Theta(n^2)$.

\textbf{Average case.} Under uniform random permutations~\cite{cormen2022}:
$T_{\text{avg}}(n)=2n\ln n+O(n)\approx 1.39\,n\log_2 n=\Theta(n\log n)$.

%======================== 8 APPLICATIONS ========================
\section{Applications}

\textbf{1. Real-time and safety-critical systems.}
Avionics flight controllers, automotive ABS, and medical pacemakers operate under
hard deadlines: a computation that runs even a millisecond too long can be
catastrophic. Engineers mandate worst-case execution time (WCET) analysis;
average-case performance is legally insufficient~\cite{kleinberg2006}.

\textbf{2. Algorithmic complexity attacks (HashDoS).}
In 2011, a denial-of-service vulnerability was disclosed in multiple web
frameworks: adversaries could send HTTP POST requests with keys that all hash to
the same bucket, degrading hash-table lookups from $O(1)$ to $O(n)$ and stalling
servers. This is a textbook example of an attacker forcing worst-case behaviour.
The fix---randomised universal hashing---restores expected $O(1)$ performance
regardless of the input~\cite{cormen2022}.

\textbf{3. Database query planning.}
PostgreSQL's query planner estimates the cardinality (number of rows matching a
predicate) to choose between a sequential scan ($O(n)$ worst case) and a B-tree
index scan ($O(\log n)$ worst case). These estimates are essentially average-case
cost models calibrated from table statistics~\cite{sedgewick2011}.

%======================== 9 CONCLUSION ========================
\section{Conclusion}

Best, worst, and average case analysis together form the complete vocabulary for
describing an algorithm's performance envelope. The key takeaways from this study
are threefold. First, worst-case analysis is the gold standard for reliability:
it provides a provable, unconditional guarantee that no input can exceed
$T_{\text{worst}}(n)$ operations. Second, average-case analysis, while closer to
everyday experience, is only as meaningful as the probability model assumed over
inputs---a limitation that practitioners must bear in mind when real-world data
deviates from a uniform distribution. Third, the asymptotic notations $O$,
$\Omega$, and $\Theta$ are mathematical bounds on functions, not synonyms for the
three cases; any bound can be applied to any case.

Building the step-by-step animation revealed an unexpected insight: the number of
array shifts in every Insertion Sort run is \emph{exactly} the number of
inversions in the original array. This bijection between a structural property of
the input and the algorithm's work count is elegant and helps explain why the
average case is $\Theta(n^2)$ even though individual runs can be as fast as
$\Theta(n)$. A natural question for further study is whether a similar
inversion-based argument applies to other comparison sorts such as Shell Sort.
